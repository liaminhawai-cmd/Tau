## 1. The directional question that now matters

Does the first theorem quantify over the shipped AI's particular call schedule, or over every legal human drag schedule? These are not the same theorem. A fixed stopping angle does not specify a unique shipped trajectory.

`applySwing(dA)` computes `steps = max(1, ceil(abs(dA)/stepMax))` and uses `step = dA/steps`. Here `CFG.substepDeg = 0.4`. Each call therefore repartitions its own angle. Repeated 1-degree calls use roughly one-third-degree internal steps; half-degree calls use quarter-degree steps. The snapshot collision solver runs after each accepted internal step. No source modification is needed for this distinction.

### Reproducible counterexample

Starting from the supplied target-1 pose, construct the 2.5-degree rigid reply, pin attacker foot 0, and swing in direction -1 through 24 degrees:

* One 24-degree call: victim `(22.5525306981406, 40.080442640703154, 11.125681692131652)`.
* Twenty-four 1-degree calls: victim `(22.554635476401728, 40.078100044174874, 11.124980476399193)`.
* Forty-eight half-degree calls: victim `(22.557297942414937, 40.07470734998331, 11.124071110512517)`.

The single-call and half-degree schedules differ by about 0.00745789 position units and 0.0922795 degrees of victim rotation, despite the same total angle to floating-point tolerance. All three produce a victim-off result in this example. **This is not a counterexample to a throw theorem. It is a counterexample to treating angle alone as a unique shipped trajectory.** The initial reply is constructed with the existing rigid-motion helper; the subsequent attack uses actual shipped `applySwing`, including its crossing and self-off checks.

`nn/research/shipped-phase-test.js` checks 24 runs spanning two initial replies, three target angles, and four input partitions. The rerun log is byte-identical. A universal human-input theorem must retain the input partition as a control variable or prove a schedule-independent enclosure. A fixed-controller theorem must explicitly state its controller policy and cannot be advertised as covering every human drag.

## 2. A newly reproduced certificate bug

`featureMargins3Interval` expects interval-valued point coordinates, but its caller passes scalar attacker coordinates. Indexing a scalar as an interval yields undefined values, which propagate to NaN. The old wall guard uses comparisons of the form `wall[0] <= 0`. For NaN, that comparison is false, so the guard can incorrectly mark the interior feature as certified.

Independent reproduction against the unmodified local baseline gave:

```text
Original walls all NaN: true
Original guard would label interior: true
```

The research patch lifts scalar points to singleton intervals, validates finite ordered endpoints, and rejects nonfinite wall output. It also refuses empty feature-regime sets rather than indexing an empty list. This does not complete a floating-point proof of the legacy geometric wall machinery. It removes a concrete false-certification path.

The old hubV shell shortcut is disabled in the research certificate path. Its omitted tangential expansion was already falsified in the earlier checkpoint, and its complete shipped snapshot enclosure remains unproved. Refusing is preferable to preserving an unsupported success result. The legacy code remains below the safety gate for reference, not as an enabled proof route.

## 3. Conditional local enclosure theorem

New module: `nn/research/shipped-apply-interval.js`.

**Statement.** Fix the shipped binary64 configuration values. Supply finite ordered intervals for the current victim pose `(x,y,rot)` and for the actual arguments `(px,py,nx,ny,sep)` entering shipped `apply`. Assume the module returns normally, so no endpoint overflow, nonfinite arithmetic, or zero-containing denominator was encountered. Then its output encloses every binary64 output of that `apply` arithmetic whose inputs lie in those intervals.

This statement is conditional on the contact arguments being enclosed. It does not assert that geometry, feature selection, contact ordering, or the drag schedule has been enclosed.

The expression tree mirrors the source:

```text
sep = min(sep, maxPenPerIter)
rx = px - current_x; ry = py - current_y
rn = rx*ny - ry*nx
wEff = 1/m + rn*rn/I
lambda = pushRelax*sep/wEff
x += (lambda/m)*nx
y += (lambda/m)*ny
rot += (lambda*rn)/I
```

Here `m=1`; `I` is computed in the same binary64 operation order as the source. In particular, the lever arm uses the **current corrected victim hub**, not the iteration-start hub. Frozen snapshot contact points may therefore yield nonzero rotation after a preceding correction.

### Proof argument

1. `next` advances or retreats the binary64 bit representation to the adjacent representable finite number, handling zero with the smallest signed subnormal. Invalid or overflowing endpoints are rejected.
2. Addition and subtraction use their monotone endpoint extrema. Multiplication and division use all four endpoint combinations; division refuses any denominator containing zero. Squaring includes zero when its input straddles zero.
3. Each rounded endpoint result is widened to its immediate predecessor and successor. Under ordinary correctly rounded binary64 basic arithmetic, these bounds enclose both the exact endpoint value and the rounded operation output. Monotonicity then encloses all inputs between the endpoints. This includes underflow to zero. Overflow is not silently accepted.
4. Structural induction over the source expression tree proves the local output enclosure. Repeated calls compose by induction provided each successive call's actual contact arguments are enclosed.

No sine, cosine, square root, or hypot assumption enters this local arithmetic theorem: the contact normal and separation are supplied inputs. That is its strength and also its limit. The argument is manually reviewable, not a proof-assistant-verified theorem.

## 4. Checks completed

The test instruments `apply` inside the actual engine source extracted by `buildEngineSource`. It records the actual before-pose, arguments, and after-pose without changing the arithmetic. It separately extracts the literal shipped `apply` body for perturbed-input checks.

* 192 actual shipped correction calls checked as singleton input boxes.
* 192 sequential conditional enclosure checks across those calls.
* 6,144 perturbed-input checks inside widened pose and argument boxes, with no escape.
* 4,518 basic interval-operation cases checked independently with exact rational endpoint extrema, including subnormal arithmetic, with no failure.
* Both main test suites rerun with byte-identical logs.
* Maximum observed replica-versus-shipped correction output discrepancy: 1.7763568394002505e-15. This measurement is not a universal replica-equivalence proof.

The exact-rational checker validates finite test cases. The universal local claim rests on the induction argument above, not on the number of tests.

## 6. What is still missing

* Enclose actual shipped contact geometry and feature selection over input sets, including floating-point trigonometry and hypot behavior.
* Enclose every feasible branch of chord pruning, closest-feature ties, deep-crossing side choice, vertical skips, caps, and horizontal-fraction floors.
* Preserve the iteration-start victim snapshot while applying corrections in exact source order, rebuilding it between iterations, up to ten iterations.
* Enclose the attacker motion and self-off/crossing vetoes for the chosen input-schedule scope.
* Prove a final foot-off margin over a covered reply family, then prove the required all-replies coverage for a dead-position claim.

None of these obligations is discharged by replaying a center trajectory or freezing its contact arguments. The new module is a reusable arithmetic component, not a finished mixed-contact propagator.

## 8. Recommended next decision

For a theorem about the whole shipped human-playable game, choose **all legal human input schedules** and retain the partition control explicitly. For a smaller first certificate, choose **the shipped AI controller's exact schedule**, label that restriction, and later generalize. Neither choice changes game physics. They change the quantifiers in the theorem.

The next research direction needs that scope decision. This checkpoint does not claim a completed proof or promise background work after the response.
